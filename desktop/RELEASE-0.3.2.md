نهج Desktop 0.3.2-rc1، مع ERPNext 16.53.0 وFrappe 16.54.0 وإضافة Payments الرسمية.

يتضمن هذا الإصدار Payments واعتمادياتها داخل صورة الخادم، بدل إضافتها في
بيئة الاختبار فقط. أُضيف كتالوج عربي من 150 رسالة، مع تعريب نصوص صفحة Paytm
والحفاظ على المتغيرات وأسماء مزودي الدفع. تُضبط مفاتيح مزود الخدمة من
إعداداته الأصلية؛ لا يحتاج إعداد الموقع المحلي إلى حساب بوابة دفع.

يحتفظ التطبيق بإمكانية تشغيل صورة 0.3.1 السابقة. يمكن استعادة نسختها
الاحتياطية إلى موقع مستقل في 0.3.2 وإضافة Payments، مع بقاء الأصل دون
تعديل وإيقاف المهام والبريد في الموقع المستعاد حتى إتمام المراجعة.
لا توجد ترقية تلقائية لقاعدة العمل، ولا يدعم الإصدار خفض ERPNext 17 إلى 16.

التثبيت على Arch بحسابك العادي:

```bash
sudo pacman -S --needed git
git clone --depth 1 --branch desktop-v0.3.2-rc1 https://github.com/9a6r/erp-nahj.git
cd erp-nahj
./desktop/install.sh --with-server
nahj-desktop
```

الحزمة الجاهزة: `nahj-desktop-0.3.2rc1-1-any.pkg.tar.zst`. افحص `SHA256SUMS`
ثم ثبّتها باستخدام `sudo pacman -U`. مثبّت المصدر أعلاه يجهّز Podman
ونطاقات المستخدم المطلوبة أيضًا. أول إعداد محلي يحتاج الإنترنت لتنزيل
صورة الخادم والخدمات، والخادم المحلي مخصص لـx86_64.

لا تُنشر هذه الحزمة إلا بعد اجتياز اختبارات Arch/Zen والتثبيت والواجهة
والعمليات الفعلية والنسخ والاستعادة والترقية المستقلة، ومراجعة الاختبارات
الأصلية كاملة. تُحفظ نتائج الاختبارين الأصليين ذوي بيانات الميزانية المعتمدة
على الشهر كما هي، مع تشخيص منفصل لحالات الحدود عبر السنة.

هذا مرشح إصدار مختبر، وليس ضمانًا لكل جهاز أو إعداد شركة. الاختبارات
لا تنفذ خصمًا حيًا لدى بوابات الدفع، ولا تتحقق من حسابات البريد والفاتورة
الإلكترونية الخاصة بمؤسستك. راجع تقرير التحقق المرتبط بالإصدار قبل اعتماد
بيانات فعلية؛ ابدأ بنسخة منفصلة من بياناتك وتحقق من الاستعادة والصلاحيات.
