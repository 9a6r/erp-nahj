# نهج — Nahj Desktop

مساحة عمل عربية لإدارة أعمالك على Linux. اجمع المحاسبة والمبيعات والمشتريات والمخزون وبقية وحدات ERPNext في تطبيق واحد، بواجهة زرقاء متناسقة مع هوية نهج ودعم العربية والإنجليزية.

## التثبيت على Arch Linux

### الحزمة الجاهزة — Arch وEndeavourOS

افتح الطرفية في النظام المثبّت على القرص. هذه الطريقة لا تحتاج إلى Git أو أدوات بناء:

```bash
curl -fLO https://github.com/9a6r/erp-nahj/releases/download/desktop-v0.3.0/nahj-desktop-0.3.0-1-any.pkg.tar.zst
curl -fLO https://github.com/9a6r/erp-nahj/releases/download/desktop-v0.3.0/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS && sudo pacman -U ./nahj-desktop-0.3.0-1-any.pkg.tar.zst
nahj-desktop
```

يتحقق الأمر من سلامة الملف ثم يثبّت التطبيق واعتمادياته باستخدام pacman. راجع حجم التنزيل والمساحة التي يعرضها pacman قبل الموافقة؛ حجم مكتبات النظام الناقصة يعتمد على الموجود في جهازك. تحتفظ الحزمة بخطوط العربية ومحرك العرض الكامل، وتستخدم المكتبات المشتركة بدل تضمين نسخ مكررة منها.

### البناء من المصدر

```bash
git clone --depth 1 --branch develop https://github.com/9a6r/erp-nahj.git
cd erp-nahj
./desktop/install.sh
nahj-desktop
```

يلزم وجود Git. يُثبّت المعالج الاعتماديات الناقصة من مستودعات Arch الرسمية باستخدام قواعد بيانات الحزم الموجودة، ثم يبني حزمة `nahj-desktop` ويدير تثبيتها عبر pacman. لا يبدأ تحديثًا شاملًا للنظام ولا يجدّد قواعد بيانات الحزم تلقائيًا. شغّل السكربت بحسابك العادي؛ سيطلب صلاحية sudo عند تثبيت حزم النظام. يدعم التطبيق جلسات Wayland وX11، ومنها Hyprland وKDE وGNOME.

إذا كانت قواعد بيانات الحزم قديمة وظهرت أخطاء تنزيل أو تعارض إصدارات، أكمل تحديث النظام باستخدام `sudo pacman -Syu` ثم أعد تشغيل السكربت. لا تستخدم `pacman -Sy` وحده؛ التحديث الجزئي غير مدعوم في Arch.

### توقف التثبيت أو ظهور Killed

إذا توقفت عملية pacman فلن يكتمل تثبيت التطبيق، وسيظهر `nahj-desktop: command not found`. كلمة `Killed` تعني أن العملية أُنهيت قسرًا؛ راجع الذاكرة والمساحة وسجل النظام لتحديد السبب:

```bash
free -h
df -h / /var/cache/pacman/pkg
journalctl -k -b --no-pager | tail -n 80
```

إذا حدث التوقف أثناء تحديث النظام، أكمل إصلاح تحديث pacman قبل إعادة تشغيل معالج التطبيق. إذا بقي قفل قاعدة بيانات الحزم، تحقق أولًا من عدم وجود عملية pacman نشطة؛ لا يحذف المعالج القفل تلقائيًا.

جلسة Live USB مؤقتة وقد تحفظ تغييرات النظام في مساحة محدودة أو في الذاكرة. استخدم النظام المثبّت على القرص للتثبيت الدائم، وتجنب تحديث نظام Live كاملًا لتجربة التطبيق. اسم أمر التشغيل هو `nahj-desktop`؛ اسم المستودع `erp-nahj` ليس أمر تشغيل.

## أول تشغيل

1. أدخل رابط خادم المؤسسة، مثل `https://erp.example.com`.
2. اضغط **اتصال وفتح مساحة العمل**. يتحقق التطبيق من الاتصال قبل حفظ العنوان.
3. سجّل الدخول بحساب عملك. تظهر الوحدات والبيانات وفق صلاحيات حسابك.

يمكنك الاتصال بخادم ERPNext/Frappe 17 قائم، أو اختيار **نظام محلي أو قاعدة بيانات خارجية** من الإعدادات لتجهيز موقع مستقل. راجع [دليل تشغيل النظام والنسخ الاحتياطي](SERVER.md). بيانات تكاملات البنوك والبريد تُضبط في إعدادات الخادم الخاصة بالخدمة. اتصال التطبيق نفسه يستخدم جلسة الحساب المعتادة ولا يحتاج API token.

استخدم HTTPS للخوادم البعيدة. يقبل التطبيق HTTP للخادم المحلي فقط، مثل `http://localhost:8000`.

## الاستخدام

- **مساحة العمل:** الوصول إلى وحدات المؤسسة.
- **المعاملات البنكية:** التسويات واستيراد الكشوف.
- **الإعدادات:** تغيير الخادم ولغة نافذة التطبيق. يمكنك العودة إلى العمل دون إعادة تحميل الصفحة أو فقدان مدخلاتها.
- **اللغة داخل البنك:** الإعدادات ← التفضيلات ← اللغة. يُحفظ الاختيار في حسابك ويُطبّق اتجاه RTL أو LTR.
- **الملفات:** اختر مكان حفظ التقارير عند التنزيل. الطباعة تستخدم نافذة النظام.

| الاختصار | الوظيفة |
| --- | --- |
| `Ctrl+R` | تحديث الصفحة |
| `Alt+Left` | رجوع |
| `Alt+Right` | تقدم |
| `Ctrl+,` | الإعدادات |

الروابط الخارجية تفتح في تطبيق النظام المناسب. تسجيل الدخول الموحد الذي ينتقل تلقائيًا إلى مزود خارجي يحتاج متصفح المؤسسة حاليًا؛ تسجيل دخول Frappe المباشر يعمل داخل التطبيق.

## التحديث والإزالة

للحزمة الجاهزة، نزّل الحزمة الجديدة وبصمتها من [صفحة الإصدارات](https://github.com/9a6r/erp-nahj/releases)، ثم ثبّتها بـ`sudo pacman -U` بعد التحقق من البصمة. للبناء من المصدر، من مجلد المشروع:

```bash
git pull --ff-only origin develop
./desktop/install.sh
```

للإزالة:

```bash
sudo pacman -Rns nahj-desktop
```

يحافظ التحديث والإزالة على إعدادات المستخدم. تُحفظ في `~/.config/nahj`، وجلسات الخوادم في `~/.local/share/nahj`، أو مسارات XDG المقابلة. لكل خادم مخزن جلسة مستقل. سجّل الخروج من حساب ERPNext قبل استخدام جهاز مشترك.

## تشخيص الاتصال

```bash
nahj-desktop --check
nahj-desktop --version
```

إذا ظهرت مساحة بيضاء داخل VirtualBox أو مع تعريف رسومي قديم، جرّب:

```bash
nahj-desktop --graphics-compatibility
```

يمكن حفظ هذا الاختيار من إعدادات التطبيق بتفعيل **توافق الرسوميات للأجهزة الافتراضية**، ثم إعادة تشغيله. يغيّر هذا الخيار طريقة نقل الصورة إلى النافذة، ويحافظ على عزل WebKit والتحقق من الشهادات. الوضع الافتراضي يستخدم مسار الرسوميات المعتاد.

- **تعذر الاتصال:** تأكد من تشغيل الخادم وصحة العنوان والوصول لشبكة المؤسسة.
- **شهادة غير موثوقة:** راجع مسؤول النظام لتثبيت شهادة صحيحة أو إعداد شهادة المؤسسة على النظام.
- **رفض الوصول:** تحقق من VPN أو سياسة الوصول لدى المؤسسة.
- **لم يُفتح التطبيق:** شغّله من جلسة Linux رسومية، وتأكد من اعتمادياته باستخدام `--check`.

## توزيعات Linux أخرى

على Debian/Ubuntu التي توفر WebKitGTK 6:

```bash
sudo apt install python3-gi gir1.2-gtk-4.0 gir1.2-webkit-6.0 gstreamer1.0-plugins-good fonts-noto-core adwaita-icon-theme
cd desktop
/usr/bin/python3 -m nahj_desktop
```

تفاصيل البناء واختبارات التشغيل في [دليل التطوير](DEVELOPMENT.md).
