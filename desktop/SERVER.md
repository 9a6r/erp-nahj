# تشغيل نظام نهج وإدارته

تتيح إعدادات التطبيق الاتصال بخادم مؤسسة موجود، أو تشغيل ERPNext محليًا مع قاعدة MariaDB محلية أو خارجية. الخادم الموجود يستخدم رابط HTTPS وحساب المؤسسة المعتاد.

## متطلبات النظام المحلي على Arch

عند البناء من المصدر:

```bash
./desktop/install.sh --with-server
```

للحزمة المثبتة مسبقًا، ثبّت `podman` و`podman-compose` و`slirp4netns` و`fuse-overlayfs` عبر pacman. شغّل نهج بحسابك العادي، مع إعداد نطاقات المستخدمين الفرعية التي يحتاجها Podman بدون root. لا يحتاج التطبيق إلى وحدة نواة خاصة به.

## موقع محلي جديد

هذا الفرع يختبر **0.3.1-rc1** على ERPNext 16.53.0 وFrappe 16.54.0. لم تُنشر صورته العامة بعد؛ اختر ملف الخادم المحلي المطابق للبصمة من الخيارات المتقدمة. التنزيل التلقائي معطّل إلى أن يُنشر الملف المتحقق منه.

اختر **نظام محلي كامل مع MariaDB**، وأدخل كلمة مرور جديدة لحساب `Administrator`، ثم اضغط **إعداد الموقع لأول مرة**. يتحقق التطبيق من SHA256 وهوية الصورة قبل إنشاء قاعدة البيانات والموقع. بعد نشر الإصدار يمكن استكمال تنزيل انقطع بدل تنزيله كاملًا من جديد.

حجم ملف الخادم الجاري نحو 1.09 جيجابايت (1.02 GiB). تحتاج صور الخدمات والقاعدة والمرفقات إلى مساحة إضافية بعد فكها؛ راقب المساحة الحرة عند الاحتفاظ بنسخ احتياطية كبيرة. يُنصح باستخدام تخزين overlay في Podman؛ التخزين VFS يكرر ملفات الصورة لكل خدمة ويستهلك مساحة أكبر بكثير.

عندما يصبح الخادم جاهزًا، تُفتح شاشة الدخول. استخدم `Administrator` وكلمة المرور التي اخترتها، ثم أكمل معالج إعداد الشركة الحقيقي. لا تُنشأ شركات أو معاملات تجريبية داخل موقعك. الواجهة المحلية متاحة للجهاز نفسه فقط، والمنفذ الافتراضي `8088`.

## MariaDB خارجية عبر TLS

اختر **خادم محلي مع MariaDB خارجية عبر TLS**. أدخل عنوان MariaDB واسم قاعدة فارغة مخصصة للموقع واسم المستخدم وكلمة مروره، واختر شهادة CA التي يوفّرها مسؤول القاعدة. يُفحص اسم الخادم والشهادة وتشفير الاتصال وتوافق MariaDB وفراغ القاعدة قبل تسجيل إعداد الموقع. يجب أن يمتلك المستخدم صلاحيات إنشاء وتعديل الجداول في القاعدة المخصصة.

يظل ERPNext وخدماته على جهازك، بينما تحفظ MariaDB الخارجية بيانات القاعدة. تبقى المرفقات في تخزين الموقع المحلي وتدخل ضمن النسخة الاحتياطية. PostgreSQL وFirebase وSupabase ليست بدائل مباشرة في هذا المسار؛ تحتاج تكاملًا منفصلًا يناسب الخدمة.

يلزم أن تكون شهادة CA صالحة للاستخدام كجهة إصدار، مع امتدادات `Basic Constraints` و`Key Usage` الصحيحة؛ يطبق Python 3.14 تحققًا صارمًا. لا يعطّل التطبيق فحص الشهادة أو اسم الخادم للتغلب على خطأ شهادة.

## التشغيل والإيقاف والاستكمال

بعد إعداد الموقع، تتيح نافذة الإدارة تشغيل الخدمات وإيقافها وعرض حالتها. الإيقاف يحتفظ بالقاعدة والملفات. تشغيل التطبيق والاتصال بموقع سابق لا يعني تلقائيًا أن خدماته تعمل؛ افتح الإدارة واضغط **تشغيل** عند الحاجة.

إذا انقطع تثبيت ERPNext بعد إنشاء الموقع الأساسي، يتيح **استكمال إعداد الموقع المحفوظ** مواصلة التثبيت دون إسقاط القاعدة أو تغيير كلمات المرور. إذا لم يكتمل إنشاء الموقع الأساسي نفسه، يظهر الخطأ وتبقى البيانات محفوظة للفحص أو الاستعادة. لا تحذف مجلد الموقع لمعالجة خطأ قبل الاحتفاظ بنسخة من بياناته.

يرفض التطبيق تشغيل أو استكمال موقع محفوظ بصورة خادم مختلفة. لا يُحوَّل موقع ERPNext 17 إلى 16 تلقائيًا. احتفظ ببياناته ونسخه الاحتياطية، واستخدم بيئته الأصلية إلى أن تُجهّز خطة نقل مدعومة ومختبرة.

## النسخ الاحتياطي

اختر مجلدًا ثم اضغط **نسخ القاعدة والملفات وإعداد الموقع**. تُصدّر نسخة جديدة تضم:

- قاعدة البيانات.
- المرفقات العامة والخاصة.
- إعداد الموقع وإعداد الخدمات وملف تعريف التشغيل وشهادة CA عند استخدام قاعدة خارجية.
- ملف بصمات SHA256 للتحقق من الملفات المصدّرة.

يجب أن تكون الخدمات قيد التشغيل. يُرفض التصدير غير المكتمل، ولا تُستبدل النسخ السابقة. تتضمن إعدادات الموقع أسرارًا ومفاتيح لازمة للاستعادة؛ احفظ النسخة في مكان خاص. لاستعادة نسخة، استخدم أدوات Frappe المناسبة لإصدار الموقع، وأعد إعداد الوصول إلى MariaDB وشهادة TLS إن كانت القاعدة خارجية.

يسجل `manifest.json` هوية صورة الخادم وإصدارات ERPNext/Frappe المعروفة وبصمات الملفات. ملف `compose.json` المصدّر يوثّق إعداد المصدر؛ لا تشغّله على جهاز آخر قبل تعديل مسارات الملفات والمنافذ والتحقق من وحدات التخزين. لا توجد في هذا الإصدار واجهة استعادة تلقائية. جرّب الاستعادة في قاعدة منفصلة، مع الاحتفاظ بمفتاح تشفير الموقع، قبل اعتماد النسخ لحماية بيانات الشركة.

## التكاملات الخارجية

بعد الاتصال، تتيح إعدادات نهج فتح **تكاملات المؤسسة والخدمات الخارجية**. تفتح هذه الشاشة مساحة Integrations الأصلية في Frappe؛ إعدادات البريد وواجهات API وOAuth وWebhooks تظل على خادم المؤسسة وتخضع لصلاحيات الحساب. أي خدمة تحتاج إضافة غير مثبّتة تُجهّز بإضافتها الرسمية وإعداداتها؛ لا يحوّل إدخال مفتاح API وحده خدمة غير مدعومة إلى تكامل جاهز. اختبر التكامل بحساب تجريبي قبل استخدام بيانات العمل.

## التخزين

تُحفظ إعدادات إدارة الموقع في `$XDG_DATA_HOME/nahj/server`، أو `~/.local/share/nahj/server` افتراضيًا. يحتفظ Podman بالقاعدة والمرفقات في وحدات تخزين مسمّاة. إزالة حزمة واجهة نهج أو إيقاف الخدمات لا يحذف هذه البيانات.

كلمة مرور مسؤول الموقع تمر إلى عملية الإنشاء ولا تُكتب في إعدادات الواجهة. يحتفظ Frappe ببيانات اتصال الموقع التي يحتاجها للتشغيل، وتُحفظ بيانات قاعدة MariaDB المحلية في ملفات خاصة بصلاحيات المستخدم.
